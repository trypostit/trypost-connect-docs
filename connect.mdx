TryPost Connect is **social publishing infrastructure**. You build your own scheduler, agent, or product. We run OAuth, token refresh, media, and native publish to 12 networks.

It is **not** the TryPost scheduler, and it is **not open source**. There is no repo to clone and no self-host install. Connect is a closed-source Cloud product at [https://connect.trypost.it](https://connect.trypost.it).

## Who it's for

You want to post to Instagram, LinkedIn, X, TikTok, and the rest from **your** product — not from our calendar.

Connect gives you that stack: connect accounts, store tokens, upload media, publish, schedule, and fire webhooks. You keep your own editor, queue, and brand. We keep the platform integrations.

If you want a finished scheduler, use [TryPost](https://app.trypost.it). If you want to run that scheduler yourself, it is [open source](/self-hosting/overview). Connect is neither of those.

## Base URL

The Connect API is available at:

```
https://connect.trypost.it/api
```

There is no `api.connect.trypost.it`. Connect is closed source — there is no self-hosted base URL and no repo to run this API yourself.

## Authentication

All API requests require a Bearer token in the `Authorization` header. You can create API keys from [Settings → API Keys](https://connect.trypost.it/settings/workspace/api-keys) or via the [`POST /api-keys`](/connect/endpoint/create-api-key) endpoint.

```bash
Authorization: Bearer YOUR_API_KEY
```

<Warning>
  Keep your API key secret. Do not expose it in client-side code or public repositories. The plain token value is only shown once at creation — store it immediately.
</Warning>

## Account scoping

Every API key is bound to the account that created it. Connect has one account per customer — not a roster of workspaces. All requests act on that account.

API keys authenticate the REST API only. Agents use the MCP server — see [MCP](#mcp).

## MCP

AI assistants talk to Connect through [MCP](https://modelcontextprotocol.io) at the same host as the app:

```
https://connect.trypost.it/mcp
```

That is **not** the scheduler MCP (`https://app.trypost.it/mcp/trypost`). Connect has one account, no workspaces, and no signatures, labels, or repurposes. Point the client at this URL or it will hit the wrong product.

### How to connect

MCP uses **OAuth 2.1** (`mcp:use`) with Dynamic Client Registration. Add the URL in your assistant, click Connect, and sign in at [connect.trypost.it](https://connect.trypost.it). No API key in the MCP config.

<Warning>
  Personal Access Tokens from [Settings → API Keys](https://connect.trypost.it/settings/workspace/api-keys) work on `/api` only. Sending `Authorization: Bearer …` on `/mcp` returns **403**. Scripts and CI should call the REST API.
</Warning>

**Cursor** — project `.cursor/mcp.json` (Cursor 1.0+):

```json
{
  "mcpServers": {
    "trypost-connect": {
      "url": "https://connect.trypost.it/mcp"
    }
  }
}
```

**Claude Code:**

```bash
claude mcp add --transport http trypost-connect https://connect.trypost.it/mcp
```

**Claude web** — [Customize → Connectors](https://claude.ai/customize/connectors) → add a custom connector named `TryPost Connect` with that URL. Leave Client ID / Secret empty.

**ChatGPT** (Pro/Plus/Business, Developer mode) — [create a connector](https://chatgpt.com/plugins#settings/Connectors?create-connector=true&redirectAfter=%2Fplugins) named `TryPost Connect`, same URL, authentication **OAuth**, no client id/secret.

Then ask: `List my Connect social accounts`.

Connected assistants live under [Settings → MCP](https://connect.trypost.it/settings/workspace/mcp).

### What the agent can do

Same surface as the REST API: create and publish posts (including per-platform `custom_content` / `custom_media`), attach media, browse the Asset Library, list content types, toggle social accounts, manage webhooks and API keys.

Connecting a **new** network is still a browser OAuth flow — [`GET /connect/{platform}`](/connect/endpoint/connect-social-account). There is no MCP tool for that.

Recommended publish path:

1. `list-social-accounts-tool` + `list-content-types-tool`
2. Pinterest / Discord: `list-pinterest-boards-tool` / `list-discord-channels-tool`
3. `create-post-tool` with `content`, optional `media[]`, and `platforms[]` (`custom_content` / `custom_media` / `meta` per network)
4. `preview-post-tool` (optional)
5. `publish-post-tool` (immediate) or `update-post-tool` with `status=scheduled`

Full tool list, parameters, and troubleshooting: [MCP](/connect/mcp).

## Billing

Two non-X accounts are free. X always counts as 1. Extra non-X accounts are $3 each / month ($30 / year).

```
quantity = xCount + max(0, nonXCount - 2)
```

Connecting beyond the free allowance (or connecting X) without an active subscription returns **402**. The same 402 applies to the rest of the API when the account no longer has app access.

## Rate limiting

API requests are throttled to prevent abuse. When you exceed the limit, the API returns a `429` status code with a `Retry-After` header indicating how many seconds to wait.

## Errors

The API uses conventional HTTP status codes. All error responses include a `message` field.

| Status | Description |
|--------|-------------|
| `200` | Success |
| `201` | Created |
| `204` | No content (successful deletion) |
| `401` | Missing or invalid API key |
| `402` | Card / active subscription required |
| `403` | Forbidden — e.g. a Viewer calling a create-post or update endpoint (including listing assets) |
| `404` | Resource not found, or resource not on this account |
| `422` | Validation error — including a rejected webhook `endpoint` (`errors.endpoint`) |
| `429` | Rate limit exceeded |

```json
{
  "message": "The name field is required."
}
```

## Response shape

Resources are returned **unwrapped** — no `data:` envelope. A single resource looks like:

```json
{
  "id": "9f1a2b3c-...",
  "name": "...",
  "...": "..."
}
```

A non-paginated collection looks like a plain array:

```json
[
  { "id": "9f1a2b3c-...", "name": "..." },
  { "id": "a1b2c3d4-...", "name": "..." }
]
```

The endpoints that wrap in `data:` are the paginated lists: [`GET /posts`](/connect/endpoint/list-posts), [`GET /assets`](/connect/endpoint/list-assets), and [`GET /webhooks/{id}/logs`](/connect/endpoint/list-webhook-logs).

There are **no** `/signatures`, `/labels`, or `/repurposes` endpoints.

## Pagination

These list endpoints paginate. They use Laravel's standard pagination envelope (`data`, `links`, `meta`) and the `page` query parameter. Page size is **25** (`meta.per_page`). There is no `per_page` query.

| Endpoint | Per page | Notes |
|---|---|---|
| [`GET /posts`](/connect/endpoint/list-posts) | **25** | Posts |
| [`GET /assets`](/connect/endpoint/list-assets) | **25** | Asset library |
| [`GET /webhooks/{id}/logs`](/connect/endpoint/list-webhook-logs) | **25** | Delivery logs for one webhook |

Example envelope for posts:

```json
{
  "data": [...],
  "links": {
    "first": "https://connect.trypost.it/api/posts?page=1",
    "last":  "https://connect.trypost.it/api/posts?page=5",
    "prev":  null,
    "next":  "https://connect.trypost.it/api/posts?page=2"
  },
  "meta": {
    "current_page": 1,
    "from": 1,
    "to": 25,
    "last_page": 5,
    "per_page": 25,
    "total": 72,
    "path": "https://connect.trypost.it/api/posts",
    "links": [
      { "url": null, "label": "&laquo; Previous", "page": null, "active": false },
      { "url": "https://connect.trypost.it/api/posts?page=1", "label": "1", "page": 1, "active": true },
      { "url": null, "label": "Next &raquo;", "page": null, "active": false }
    ]
  }
}
```

Use the `page` query parameter to navigate. Other list endpoints (social accounts, API keys, webhooks) return all items without pagination, as a plain array.
