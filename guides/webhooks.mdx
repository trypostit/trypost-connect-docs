Create an outgoing webhook with [`POST /webhooks`](/api-reference/webhooks/create). Connect `POST`s a JSON envelope to your `endpoint` and signs the body.

Private, loopback, and link-local URLs are rejected (`422` on `errors.endpoint`). Connect does not follow redirects — `3xx` is a failure. Respond `2xx` (including `204`) as soon as you accept the payload.

## Events

| Event | When |
|---|---|
| `post.created` | Draft saved |
| `post.scheduled` | Status becomes `scheduled` |
| `post.unscheduled` | Scheduled post returns to `draft` |
| `post.published` | Every enabled platform succeeded |
| `post.partially_published` | Mixed success |
| `post.failed` | Every enabled platform failed |
| `post.deleted` | Post deleted |
| `account.connected` | Social account connected or reconnected |
| `account.disconnected` | Social account disconnected |

There is no `publishing` event and no wildcard. Immediate publish goes `draft` → `publishing` (silent) → outcome event. A due scheduled post does the same.

Edits that do not change status send nothing.

## Envelope

```json
{
  "id": "9f1a2b3c-4d5e-6f7a-8b9c-0d1e2f3a4b5c",
  "type": "post.published",
  "data": {},
  "created_at": "2026-09-04T15:04:05+00:00"
}
```

| Field | Description |
|---|---|
| `id` | Delivery log UUID. Stable across retries of the same attempt. A [replay](/api-reference/webhooks/replay) gets a new id. |
| `type` | Event name, or `webhook.test` for a ping |
| `data` | Event payload. Empty object for `webhook.test`. Post events and account events use the shapes below. |
| `created_at` | ISO 8601 of **this attempt**. Retries keep `id` and write a new timestamp. |

### `data` on post events

`id`, `account_id`, `user_id`, `status`, `created_via` (`api` \| `mcp` \| `web` \| `null`), `content`, `scheduled_at`, `published_at`, `created_at`, `updated_at` (ISO 8601), `author` (`{id,name}` or `null`), `account` (`{id,name}`), `media[]`, `platforms[]`.

Each `platforms[]` row includes `id`, `social_account_id`, `platform`, `content_type`, `custom_content`, `custom_media`, `enabled`, `status`, `platform_post_id`, `platform_url`, `published_at`, `error_message`, `error_context`, display snapshots, `meta`, and a nested `social_account` (`id`, `platform`, `display_name`, `username`, `avatar_url`, `status`).

### `data` on `account.connected` / `account.disconnected`

`id`, `account_id`, `platform`, `display_name`, `username`, `avatar_url`, `status`, `created_at`, `updated_at`.

Dedupe on `id`. Do not treat the full body as byte-identical across retries — `created_at` (and therefore the signature) changes.

## Headers

| Header | Value |
|---|---|
| `Content-Type` | `application/json` |
| `X-Webhook-Signature` | Hex HMAC-SHA256 of the **raw request body** |
| `User-Agent` | `TryPost.it/1.0 (+https://trypost.it)` |

## Verify the signature

HMAC-SHA256 the **raw body bytes** with the signing secret. Compare the hex digest to `X-Webhook-Signature` with a constant-time comparison. Do not re-serialize the JSON.

<CodeGroup>
```javascript Node.js
import crypto from 'node:crypto';

const expected = crypto
  .createHmac('sha256', process.env.TRYPOST_WEBHOOK_SECRET)
  .update(rawBody)
  .digest('hex');

const valid = crypto.timingSafeEqual(
  Buffer.from(expected, 'utf8'),
  Buffer.from(req.headers['x-webhook-signature'], 'utf8'),
);
```

```php PHP
$expected = hash_hmac('sha256', $rawBody, $secret);
$valid = hash_equals($expected, $request->header('X-Webhook-Signature'));
```

```python Python
import hmac
import hashlib

expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
valid = hmac.compare_digest(expected, signature_header)
```
</CodeGroup>

<Warning>
  Read the unparsed body (for example Express `express.raw({ type: 'application/json' })`) and only then `JSON.parse`.
</Warning>

Create, get, and rotate return `signing_secret`. List and update omit it. Rotate invalidates the previous secret immediately — including the next retry of an in-flight delivery.

`status` is `enabled`, `disabled`, or `paused`. Connect pauses a webhook after repeated failures (`paused_at` set). You cannot send `paused` on create or update — re-enable with `PUT` `status=enabled`. A [replay](/api-reference/webhooks/replay) still delivers even while paused or disabled.

Test with [`POST /webhooks/{id}/send-test`](/api-reference/webhooks/send-test) (`type` is `webhook.test`). Creating a webhook does **not** ping the URL.
